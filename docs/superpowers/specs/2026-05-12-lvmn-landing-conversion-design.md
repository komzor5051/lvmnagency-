# Лендинг LVMN — редизайн под конверсию в заявки

Дата: 2026-05-12
Статус: согласован, готов к плану реализации

## Проблема

Текущая главная (`app/page.tsx`) — журнал-эссе личного бренда: masthead «Vol. iv · no. 12», drop-cap, заголовок про автора («Как я делаю скучный AI, который работает»). Красиво и отстраивает, но конверсионно слабо:

- Hero не отвечает за 3 секунды на «для кого / какой результат / что делать дальше».
- Первичный CTA — `Написать →` (anchor на `#Контакт` внизу), без формы и без понимания, что произойдёт после.
- Социальных доказательств на странице нет: отзывов нет, логотипов нет, метрики кейсов не подтверждены клиентами (выглядят как плейсхолдеры — «Retail-сеть (НДА)», «−38%»).
- Уже существующий мощный lead-magnet — интерактивный AI-аудит на `/audit` (пошаговая форма → LLM-разбор → захват Telegram → уведомление владельцу → CTA на созвон) — с главной не используется.
- Аналитики «толком нет» — нельзя понять, где воронка проседает.

Цель редизайна: больше заявок. Подход — редизайн hero и оффера сразу (вариант B из обсуждения подходов), сохраняя визуальный язык сайта (вариант A из обсуждения hero: журнал + конверсионный слой).

## Решение (обзор)

Сохраняем всю типографику и палитру (`S` токены в `page.tsx`: `bg #f6f2ea`, `fg #1a1815`, accent `oklch(0.55 0.12 30)`, Fraunces / Inter / JetBrains Mono), masthead, drop-cap. Добавляем конверсионный слой и честные доказательства; убираем неподтверждённые метрики; подключаем аналитику.

Lead-magnet: бесплатный созвон 30 минут. Мягкая точка входа — существующий AI-аудит на `/audit` (он сам ловит контакт и ведёт на созвон).

Риск, принят сознательно: без соц-доказательств hero держится на ясности оффера + AI-аудите как демонстрации компетентности + risk-reversal. Потолок конверсии ограничен; сбор реальных отзывов/цифр — приоритетная задача СЛЕДУЮЩИМ шагом, вне скоупа этого редизайна.

## Скоуп

### 1. Hero (`app/page.tsx`, секция HERO)

Сохранить: masthead, `Л<em>ями</em>н`, drop-cap, сетку `5fr 7fr`, портрет-плейсхолдер.

Изменить/добавить:
- **Подзаголовок-уточнение** под `<h1>`: кто клиент + результат. Ориентир: «Для среднего бизнеса в РФ: за 30 минут разбора показываю, где ИИ реально экономит деньги — и сколько именно. 40+ внедрений, ни одного пилота, оставшегося пилотом.» (точную формулировку утвердить при реализации).
- **Первичный CTA**: `Пройти бесплатный AI-аудит →` → `/audit` (вместо `#Контакт`).
- **Вторичный CTA**: `посмотреть кейсы` → `#Работы` (остаётся, текст уточнить).
- **Бейдж дефицита**: «Беру 2 проекта в мае» (сейчас мелким в masthead) — продублировать заметно рядом с CTA.
- **Proof-bar под линией fold**: только честное — `40+ внедрений · 200+ обучено · в AI с 2023` + ссылки `Telegram / GitHub`. Без фейковых логотипов.

### 2. Секция «Работы» → «Типы задач» (`app/page.tsx`, секция WORKS + `CASES`)

- Убрать неподтверждённые метрики (`metric`, `metric_label`). Оставить тип задачи + ниша + тег. Подзаголовок секции: «детали и цифры — голосом, под NDA».
- Заменить `Placeholder` (диагональная штриховка) на минималистичные типографические обложки: крупная метка задачи + тег на фоне `S.card`. Без стоковых картинок и AI-генерации изображений.
- Карточки кликабельны → `/audit` (вместо `#Контакт`).

### 3. Middle CTA (`app/page.tsx`, после секции SERVICES)

Добавить кнопку `Записаться на бесплатный созвон →` → `/audit` после секции «Услуги» (там уже есть текст «выбираем вместе на первом созвоне», но кликнуть некуда).

### 4. Sticky mobile CTA-бар (новый компонент)

Узкая фиксированная полоса снизу экрана на мобайле (`@media max-width: 768px`): `Бесплатный AI-аудит →` → `/audit`. На десктопе скрыт. Нейтральный, в палитре сайта. Файл: `components/landing/StickyMobileCTA.tsx` (или встроить в `page.tsx` стилями — на усмотрение реализации).

### 5. Контактная секция + роут заявки

- В секции CONTACT над кнопками `Telegram/GitHub/Email` добавить мини-форму заявки на созвон: 3 поля — имя, чем занимается бизнес, Telegram/телефон. Кнопки-контакты остаются как альтернатива.
- Новый API-роут `app/api/lead/route.ts` по образцу `app/api/audit/route.ts`: POST с полями формы → уведомление в Telegram через `AUDIT_BOT_TOKEN` / `AUDIT_NOTIFY_CHAT_ID` (переиспользуем существующие env-переменные; если решим разделить — `LEAD_BOT_TOKEN` / `LEAD_NOTIFY_CHAT_ID`). Без LLM, без хранения в БД на первом этапе. Валидация обязательных полей, fire-and-forget на отправку.

### 6. Аналитика

- **PostHog**: добавить `posthog-js`, инициализация в layout/провайдере, включить session recordings. Env: `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`.
- **Яндекс.Метрика**: уже подключена (`components/YandexMetrika.tsx`) — добавить цели через `ym(id, 'reachGoal', ...)`.
- События (одинаковые имена в обоих): `hero_cta_click`, `cases_cta_click`, `middle_cta_click`, `sticky_cta_click`, `audit_started`, `audit_completed`, `lead_form_submit`, `tg_click`. (`audit_started` / `audit_completed` — на странице `/audit`.)

## Поток данных (заявка на созвон)

1. Пользователь жмёт CTA → `/audit` (основной путь) ИЛИ заполняет мини-форму в секции CONTACT.
2. Мини-форма → `POST /api/lead` → валидация → `sendMessage` в Telegram владельцу (fire-and-forget) → ответ `{ ok: true }`.
3. На фронте после успешного ответа — событие `lead_form_submit` (PostHog + Я.Метрика), показ состояния «отправлено, отвечу в течение суток».
4. `/audit` остаётся как есть (POST `/api/audit`), но на главной теперь на него ведут 4 CTA-точки.

## Обработка ошибок

- `/api/lead`: 400 при отсутствии обязательных полей; 500 при внутренней ошибке; ошибка отправки в Telegram не валит ответ пользователю (как в `/api/audit`).
- Фронт мини-формы: дизейбл кнопки на время запроса, явное сообщение об ошибке с предложением написать в Telegram напрямую.
- PostHog/Метрика: события — best-effort, не блокируют переходы; при отсутствии env PostHog не инициализируется.

## Тестирование

- `npm run build` и `npm run lint` проходят.
- `/api/lead`: ручной POST (валидный → 200 + сообщение в Telegram-тест; невалидный → 400).
- Визуально: hero на десктопе и мобайле, sticky-бар появляется только на мобайле и не перекрывает контент/футер, все 4 CTA ведут на `/audit`, мини-форма отправляется и показывает успех.
- События видны в PostHog (live events) и в Я.Метрике (цели).
- Регрессии: остальные секции главной (`/`), страницы `/blog`, `/audit`, `/ai-audit` не сломаны.
