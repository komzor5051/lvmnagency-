# Codex и Claude Code на одной машине: как я разделил работу между ними

На моём ноутбуке стоят оба агента. Codex CLI 0.153.4 на модели gpt-6-astra и Claude Code 2.1.266. Устроены они внутри по-разному, поэтому и живут рядом.

Дальше — чем они расходятся по фактам, а не по маркетингу, и по какому признаку я отдаю задачу одному или другому. Бенчмарков не будет, в конце объясню почему.

## Разные файлы, одна идея

Первое, что видишь при установке — оба хотят, чтобы ты объяснил им правила проекта.

У Claude Code это `CLAUDE.md`, у Codex — `AGENTS.md`. Работают одинаково: файл в корне репозитория, файлы во вложенных папках перебивают корневой, глобальный лежит в домашней директории. У меня `~/.codex/AGENTS.md` на 105 строк и `~/.claude/CLAUDE.md` на 102. Объём почти одинаковый, и это не совпадение: оба файла грузятся в каждую сессию, поэтому за длиной приходится следить.

Настройки расходятся сильнее. Codex живёт в TOML: `~/.codex/config.toml`, где лежит модель, уровень reasoning и список доверенных папок.

```toml
model = "gpt-6-astra"
model_reasoning_effort = "high"

[projects."/Users/lvmn/Desktop/Бизнес/lvmn-site"]
trust_level = "trusted"
```

Кастомные агенты у Codex — тоже TOML-файлы, каждый отдельным файлом в `~/.codex/agents/`. У меня их там 24. У Claude Code настройки в JSON, а агенты и скиллы — markdown с фронтматтером.

Разница не косметическая. TOML-конфиг проще править скриптом и держать в git, markdown-агенты проще писать руками и читать глазами.

## Песочница: где заканчивается доверие

У Codex три уровня песочницы: `read-only`, `workspace-write` и `danger-full-access`. По умолчанию стоит второй — писать можно в рабочую папку, лезть в сеть нельзя. Отдельная деталь, которая мне нравится: если проект не под контролем версий, дефолт автоматически падает до `read-only`. Логика простая — нет git, нечем откатиться, значит не даём писать.

У Claude Code режимов шесть: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. С 14 августа 2026 на планах Pro, Max и Team новые сессии стартуют в `auto` — агент делает всё сам, а безопасность проверяется фоном.

Ещё у Codex есть штука под названием Guardian. Это отдельный агент-ревьюер: он смотрит на запросы к инструментам вместо тебя и дёргает человека только там, где риск настоящий. OpenAI описывает его в отдельном материале про авто-ревью агентных действий.

Разница по умолчанию такая: Codex стартует в `workspace-write`, Claude Code на планах Pro, Max и Team — в `auto`. У Codex граница жёстче и задана на уровне процесса, у Claude Code больше ручек, и ими надо уметь пользоваться.

## Что появилось у обоих за лето

Обе команды за лето пришли к одним и тем же решениям почти одновременно.

Worktrees — изолированный чекаут репозитория, в котором агент возится, не трогая твою рабочую копию. У Codex появился в августе как экспериментальный: флаг `--worktree` и команда `/worktree`. У Claude Code свой `--worktree` плюс хуки на создание и удаление, так что можно повесить установку зависимостей на каждый новый чекаут.

С плагинами похоже. У Codex 3 сентября появился plugin CLI с командами list, install и remove, а каталог у него общий с ChatGPT — включённое в приложении видно в терминале. У меня там 15 штук. У Claude Code плагины ставятся из маркетплейсов, zip-архивов и локальных папок.

Субагенты есть у обоих, и оба предупреждают про расход токенов. Про них я написал [отдельно](/blog/subagenty-kogda-ekonomyat-a-kogda-zhgut-tokeny), потому что тема стоит денег.

## Как я делю задачи

Правило, к которому я пришёл: Codex получает изоляцию, Claude Code получает процесс.

Codex получает задачи, где важно, чтобы агент долго молотил в песочнице и не спрашивал: обход большого репозитория, рефакторинг, разбор чужого кода. Guardian отсекает опасное, `workspace-write` не даёт вылезти за папку.

Claude Code получает то, где важен мой рабочий процесс: контент, скиллы, хуки, задачи с проверками на выходе. У него 32 события для хуков — от старта сессии до попытки завершить работу — и это тот слой, который превращает агента из умного собеседника в конвейер.

Есть и третий вариант, про который забывают: держать общие скиллы. Codex читает их из `~/.agents/skills`, Claude Code — из `~/.claude/skills`, формат `SKILL.md` у обоих одинаковый. У меня в общей папке 32 скилла. Часть полей фронтматтера Claude Code не понимает Codex — что именно теряется, я разобрал [отдельно](/blog/odin-nabor-skillov-na-claude-code-i-codex).

## Почему тут нет бенчмарков

Я собирался поставить сюда табличку. Открыл сравнения, которые гуляют по сети, и обнаружил в них цифры вроде «97,0% на SWE-bench Verified против 85,8% на Terminal-Bench». Разные бенчмарки, сведённые в одну строку, будто это соревнование на одной дистанции.

Первоисточника ни у одной цифры я не нашёл. Поэтому в статью они не попали.

Практический вывод от этого не меняется. Выбор между агентами решается тем, какой у тебя процесс, а не таблицей с процентами. Что люди в этих процессах делают на самом деле, я разбирал [здесь](/blog/issledovanie-kak-lyudi-rabotayut-s-claude).

Собранный конвейер под контент — папка с фото и видео на входе, Reel, пост и карусель на выходе — я описал в гайде [ContentOS](https://vladlyamin.ru/products/codex-content-os). Раздел про установку там разбирает оба варианта, Codex и Claude Code, стартовый код идёт в комплекте.
